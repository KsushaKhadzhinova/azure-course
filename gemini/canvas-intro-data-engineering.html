Архитектурный конспект: Начало работы с проектированием данных в Azure

TL;DR: Инженер данных (Data Engineer) — это архитектор и строитель фундамента для всей аналитики в компании. Он отвечает за то, чтобы сырые, разрозненные данные (структурированные и неструктурированные) были надежно собраны, очищены, преобразованы и сложены в высокопроизводительные хранилища (Lakehouse, Data Warehouse), где их смогут использовать дата-аналитики и ИИ-модели.

Модуль 1. Типы обрабатываемых данных

Инженеры данных ежедневно работают с разнородными системами, которые генерируют информацию в разных форматах. В архитектуре выделяют три основных типа данных:

Рис 1. Слева направо: Структурированные (Таблицы), Полуструктурированные (JSON), Неструктурированные (Документы).
Тип данных Описание и структура Примеры
Структурированные Имеют жесткую, заранее определенную схему. Данные строго выровнены по строкам и столбцам. Реляционные БД (SQL Server), плоские CSV-файлы со строгой типизацией.
Полуструктурированные Имеют иерархию или теги, но не обязаны вписываться в жесткую таблицу. Часто требуют "сглаживания" (flattening) перед аналитикой. Файлы JSON, XML, YAML, базы данных NoSQL (Azure Cosmos DB).
Неструктурированные Не имеют предопределенной схемы или табличной структуры вообще. Часто обрабатываются методами машинного обучения. PDF-документы, изображения, видео, аудиофайлы, свободный текст.

Модуль 2. Основные операции инженера данных (Data Operations)

Работа инженера заключается в создании конвейеров (pipelines), которые автоматизируют движение данных. Выделяют три ключевых этапа:

1. Интеграция данных:
Установка защищенных связей (Linked Services) между операционными базами (источниками) и аналитическими системами для безопасного извлечения.
2. Преобразование (ETL/ELT):
Парсинг JSON, очистка от дублей, фильтрация и приведение сырых операционных данных к удобному для аналитики формату.
3. Консолидация:
Слияние (Merge) потоков из десятков разных систем (ERP, CRM, логи) в единое централизованное хранилище или Озеро данных.

Модуль 3. Языки программирования инженера данных

В отличие от аналитиков, которые в основном работают с BI-инструментами и DAX, инженеры данных должны свободно владеть скриптовыми языками для написания трансформаций и оркестрации:

  • SQL: Классический и обязательный язык для манипуляции табличными данными (SELECT, INSERT, UPDATE, DELETE).
  • Python (PySpark): Стандарт де-факто для Big Data. Используется в Jupyter/Fabric ноутбуках для описания сложной логики преобразований, которая затем выполняется распределенно на кластерах Apache Spark.
  • KQL (Kusto Query Language): Мощнейший язык Microsoft для мгновенного полнотекстового поиска и агрегации высокоскоростных потоковых данных (логов, телеметрии IoT) в службах Azure Data Explorer и Fabric Real-Time Intelligence.

Модуль 4. Архитектурные концепции хранения и обработки

Операционные (OLTP) vs Аналитические (OLAP) данные

Инженер данных работает на стыке двух миров. Он извлекает данные из операционных систем (баз данных приложений, которые пишут транзакции в реальном времени), трансформирует их и загружает в аналитические системы (оптимизированные для чтения миллионов строк аналитиками).

Озера данных (Data Lakes):
Дешевое хранилище для гигантских объемов (петабайты) сырых данных в любых форматах без предварительной схемы (Schema-on-read).
Хранилища данных (Data Warehouses):
Дорогие, но сверхбыстрые реляционные СУБД. Данные строго структурированы (Звезда/Снежинка) и оптимизированы для SQL-запросов.
Apache Spark & Lakehouse:
Spark — это движок параллельной обработки в памяти. Lakehouse объединяет дешевизну Озера и транзакционность Хранилища (ACID) с помощью формата Delta Lake.

Конвейеры (Pipelines) и Потоки (Streaming)

Для автоматизации движения данных инженеры строят Конвейеры (Data Pipelines) — оркестраторы процессов ETL/ELT, которые запускаются по расписанию или по событию.

Однако не все данные могут ждать ночной пакетной загрузки. Для телеметрии устройств Интернета вещей (IoT) или фидов социальных сетей применяется Потоковая передача данных (Streaming), которая захватывает данные и в реальном времени объединяет их с историческими пакетами.

Модуль 5. Экосистема проектирования данных в Azure

Microsoft Azure включает широкую экосистему служб для маршрутизации, хранения и обработки потоков данных корпоративного уровня.

Рис 2. Конвейер корпоративной аналитики: Операционные данные (Источники) -> Прием данных (ETL) -> Хранение и обработка -> Моделирование и визуализация.

Ключевые технологии Microsoft для Data Engineering:

  • Azure Data Factory: Главный оркестратор ETL. Позволяет визуально конструировать перемещение данных из сотен источников по расписанию.
  • Azure Data Lake Storage Gen2 (ADLS Gen2): Фундаментальное хранилище "озера". Безопасное, масштабируемое, поддерживающее иерархическое пространство имен (POSIX).
  • Azure Stream Analytics: Сервис для обработки горячих потоковых данных (например, от брокеров событий, таких как Event Hubs).
  • Azure Databricks: PaaS-платформа на базе Apache Spark для масштабной очистки данных, инженерии и ИИ.
  • Microsoft Fabric: Единая SaaS-платформа, которая объединяет все вышеперечисленное поверх общего озера данных OneLake. Включает Fabric IQ — рабочую среду для объединения бизнес-семантики и систем ИИ.

Как выбрать правильную архитектуру?

При построении аналитического решения команды разработчиков сталкиваются с выбором ролей, хранилищ и технологий.
