# Введение в инженерию данных в Azure

**Источник:** https://learn.microsoft.com/en-us/training/modules/introduction-to-data-engineering-azure/

## Цель модуля

Понять роль инженера данных (data engineer), основные операции с данными (интеграция, трансформация, консолидация), ключевые концепции (операционные и аналитические данные, потоковые данные, пайплайны, data lake, data warehouse, lakehouse, Apache Spark) и сервисы Azure, которые используются для этих задач.

## Ключевые понятия

- **Data engineer (инженер данных)** - роль, которая интегрирует, трансформирует и консолидирует данные из структурированных и неструктурированных систем в структуры для аналитики; обеспечивает производительность, эффективность и надежность пайплайнов и хранилищ.
- **Структурированные данные** - данные из табличных систем (реляционные БД, CSV), строки и столбцы выровнены единообразно.
- **Полуструктурированные данные** - например, JSON; часто требуют выравнивания (flattening) перед загрузкой.
- **Data integration (интеграция)** - установка связей между операционными и аналитическими сервисами и источниками данных.
- **ETL / ELT** - извлечение, трансформация и загрузка; вариант ELT сначала загружает данные в data lake, затем трансформирует их "большими" методами обработки.
- **Data consolidation (консолидация)** - объединение данных из нескольких источников в единую структуру для аналитики и отчетности.
- **Operational vs analytical data** - операционные данные - транзакционные, создаются приложениями; аналитические - оптимизированы для анализа и отчетности, часто в data warehouse.
- **Streaming data (потоковые данные)** - непрерывные данные в реальном времени, например от IoT-устройств или социальных лент.
- **Data pipeline (пайплайн данных)** - оркестрация действий по переносу и трансформации данных; запускается по расписанию или по событиям.
- **Data lake (озеро данных)** - хранилище больших объемов данных в исходном, сыром формате; схема применяется при чтении.
- **Data warehouse (хранилище данных)** - централизованное хранилище интегрированных текущих и исторических данных в реляционных таблицах со схемой для аналитики.
- **Lakehouse (лейкхаус)** - сочетание масштабируемости data lake и возможностей запросов data warehouse на основе формата Delta Lake (транзакции ACID, принудительная схема); основная архитектура Microsoft Fabric.
- **Apache Spark** - фреймворк параллельной обработки с обработкой в памяти и распределенным хранением; PySpark - Python API для Spark.
- **KQL (Kusto Query Language)** - язык запросов для потоковых и журнальных данных в аналитике реального времени.
- **Microsoft Fabric** - SaaS-платформа аналитики на базе OneLake.

## Содержание по урокам

### 1. Введение
Источник: https://learn.microsoft.com/en-us/training/modules/introduction-to-data-engineering-azure/1-introduction

Во многих организациях инженер данных - ключевая роль для интеграции и консолидации данных в структуры, пригодные для аналитики. Азурный инженер данных также отвечает за производительность, эффективность, организацию и надежность пайплайнов и хранилищ.

### 2. Что такое инженерия данных
Источник: https://learn.microsoft.com/en-us/training/modules/introduction-to-data-engineering-azure/2-what-data-engineering

- **Типы данных**: структурированные (таблицы, CSV), полуструктурированные (JSON, часто требуют выравнивания), неструктурированные.
- **Операции**: интеграция (связь систем для доступа к данным), трансформация (ETL или ELT, приведение структуры и формата для анализа), консолидация (объединение данных из нескольких источников в аналитические хранилища - data lake или data warehouse).
- **Языки**: SQL (SELECT, INSERT, UPDATE, DELETE для работы с таблицами); Python (анализ данных, ноутбуки, в больших нагрузках - PySpark для трансформаций); KQL (потоковые и журнальные данные в Microsoft Fabric Real-Time Intelligence и Azure Data Explorer); другие (R, Java, Scala, C# и др.), в том числе в ноутбуках с разными языками.

### 4. Важные концепции инженерии данных
Источник: https://learn.microsoft.com/en-us/training/modules/introduction-to-data-engineering-azure/4-common-patterns-azure-data-engineering

- **Операционные и аналитические данные**: задача инженера - интегрировать источники, извлечь данные из нескольких систем, трансформировать их и загрузить в аналитическое хранилище (ETL-решения).
- **Потоковые данные**: события в реальном времени (IoT, социальные ленты); их нужно захватывать и загружать в аналитические системы, часто вместе с пакетными данными приложений.
- **Пайплайны данных**: повторяемые ETL-решения, которые запускаются по расписанию или событиям.
- **Data lake**: хранит данные в исходном, нетрансформированном виде; масштаб - терабайты и петабайты; в отличие от data warehouse, трансформация не выполняется при загрузке.
- **Data warehouse**: централизованное интегрированное хранилище текущих и исторических данных в реляционных таблицах; инженер проектирует его и управляет регулярными загрузками.
- **Lakehouse**: одна система для сырых файлов и структурированной аналитики в формате Delta Lake (ACID, принудительная схема); инженеры используют Spark и ноутбуки, аналитики - SQL, без перемещения данных между системами.
- **Apache Spark**: параллельная обработка с распределенным хранением; инженер должен уметь работать с ним через ноутбуки и кодовые артефакты.

### 5. Инструменты данных в Microsoft Azure
Источник: https://learn.microsoft.com/en-us/training/modules/introduction-to-data-engineering-azure/5-common-tooling-azure-data-engineering

- Операционные данные хранятся в Azure SQL Database, Azure Cosmos DB и Microsoft Dataverse; потоковые данные захватываются брокерами событий, например Azure Event Hubs.
- Основные технологии для инженерии данных: Microsoft Fabric, Azure Data Lake Storage Gen2, Azure Stream Analytics, Azure Data Factory, Azure Databricks.
- **Microsoft Fabric** - SaaS-платформа на OneLake, объединяющая data engineering, data factory, data science, data warehousing, real-time intelligence, databases и BI; также включает Fabric IQ (preview).
- Azure Synapse Analytics также входит в решение; для миграции Synapse-нагрузок в Fabric есть руководство Microsoft.
- Аналитические хранилища, наполняемые инженерами, используются для моделирования и визуализации, часто в Power BI.

## Что запомнить

- Инженер данных интегрирует, трансформирует и консолидирует данные для аналитики и обеспечивает надежность пайплайнов.
- ETL трансформирует данные до загрузки; ELT загружает сырые данные в data lake и трансформирует их после.
- Data lake хранит данные в исходном виде, data warehouse - в структурированном виде для аналитики, lakehouse объединяет оба подхода на базе Delta Lake.
- Потоковые данные (IoT, события) требуют отдельного захвата и обработки в реальном времени.
- Основные инструменты Azure для инженерии данных: Microsoft Fabric, Azure Data Lake Storage Gen2, Azure Stream Analytics, Azure Data Factory, Azure Databricks.
